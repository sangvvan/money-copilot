# M1 — Foundation & Security

## Goal

Create a locally runnable skeleton and establish security boundaries before ingesting any financial data.

## Deliverables

- Monorepo structure: `apps/web`, `apps/api`, `docs`
- Next.js + TypeScript web shell
- FastAPI service with health endpoint
- PostgreSQL and migrations
- Docker Compose development environment
- Passkey/WebAuthn registration and authentication
- User, credential and session persistence
- Secure configuration validation
- Redaction-safe structured logging
- Unit/integration tests
- CI: lint, typecheck and tests

## Acceptance criteria

1. A fresh clone starts using documented commands.
2. MVP does not require password authentication.
3. WebAuthn challenges are single-use and expire.
4. RP ID and allowed origins are configuration-driven and validated.
5. Tests cover challenge replay, challenge expiry and invalid origins.
6. Session cookies are HttpOnly/Secure in production and sessions expire.
7. Secrets come from environment configuration; local `.env` files are ignored.
8. Logs contain no credential material or financial payload.
9. All test/fixture financial information is synthetic.
10. CI passes.

## Out of scope

No Gmail ingestion, VCB parser, dashboard, AI categorization or production deployment in M1.

## Review gate

M2 must not begin until the owner verifies the M1 security behavior and approves the implementation PR.
